Junior Cloud / DevOps Portfolio

Praxisnahes Docker-/DevOps-Lab mit Betriebsfokus

Dieses Portfolio zeigt nicht nur, dass Container gestartet werden können, sondern dass Betriebszustände geprüft, Fehlerfälle simuliert, Backups getestet, Secrets geschützt und technische Arbeit nachvollziehbar dokumentiert wird.

GitHub Repository öffnen Dokumentation ansehen
Docker Docker Compose Redis Backup/Restore Monitoring GitHub Actions

Projektfokus

  • Containerbetrieb: Dockerfile, Compose, Web-App, Redis
  • Betriebssicherheit: Healthchecks, Readiness, Restart Policy
  • Daten & Recovery: persistentes Volume, Backup, Restore-Test
  • Observability: Logging, Prometheus, Grafana, cAdvisor
  • Automation: CI-Prüfung mit GitHub Actions

Kompetenzbereiche

Was im Projekt praktisch umgesetzt wird

Die Landingpage fasst die wichtigsten Themen zusammen. Die technische Tiefe liegt weiterhin im Repository und in den Dokumentationsdateien.

Containerbetrieb

Aufbau eines kleinen Web-/Redis-Stacks mit Dockerfile, Docker Compose und getrennten Development- und produktionsnahen Konfigurationen.

Health & Readiness

Prüfung von Containerzuständen, Healthchecks, Start-Abhängigkeiten und Stack-Readiness aus Betriebssicht.

Backup & Restore

Redis-Volume-Backup, Restore-Test und Dokumentation des Grundsatzes: Ein Backup ist erst nach erfolgreichem Restore-Test belastbar.

Security & Secrets

Lokales Secret-Handling, Schutz durch .gitignore und .dockerignore, keine echten Secrets im Repository.

Monitoring & Logging

Grundlagen mit Docker-Logs, Terminal-Session-Logging sowie Monitoring-Lab mit Prometheus, Grafana und cAdvisor.

CI & Automatisierung

GitHub Actions prüft Compose-Konfiguration, baut das Image, startet den Stack und testet Web sowie Redis im Runner.

Nachweis

Was dieses Projekt zeigt

Das Projekt ist bewusst als Lern- und Portfolio-Lab aufgebaut. Es soll keine vollständige Enterprise-Produktionsumgebung vortäuschen, sondern wichtige Betriebsprinzipien praktisch nachweisen.

01

Ich kann Docker-Stacks strukturiert aufbauen, starten und prüfen.

02

Ich kann Betriebszustände, Healthchecks und Readiness bewerten.

03

Ich kann einfache Ausfälle simulieren und Diagnosewege dokumentieren.

04

Ich beachte Security-Grundlagen, Secret-Handling und Repository-Hygiene.
